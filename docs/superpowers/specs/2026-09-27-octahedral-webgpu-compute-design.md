# M5 P4b — WebGPU-resident octahedral compute

Date: 2026-09-27  
Issue: #15  
Baseline: `d4d883a036c4f77f6b39e7c1bbac3bb915c18459`

## 1. Goal

Move the accepted octahedral Link physics step onto WebGPU without uploading dynamic vertex state from JavaScript on ordinary ticks.

P4b is compute-only. It establishes a real WebGPU-resident state and a CPU/GPU differential boundary. P4c will render directly from the same WebGPU position buffer.

The accepted CPU path remains the semantic/behavioral reference and fallback.

## 2. Why WebGPU compute alone is not enough

The accepted P3 renderer is WebGL/Three and consumes an RGBA32F `DataTexture`.

If compute runs in WebGPU but rendering stays on that WebGL texture, every frame still needs:

```text
WebGPU state
  -> GPU readback / CPU-visible copy
  -> JavaScript staging
  -> WebGL texture upload
```

That does not solve the P4a bandwidth bottleneck.

Therefore P4 is explicitly split:

- **P4b:** GPU-resident physics state + differential witness;
- **P4c:** WebGPU-native rendering from that exact position buffer.

## 3. State ownership

The P4b controller owns these WebGPU storage buffers:

```text
positions   Float32[linkCount * vertexCount * 3]
velocities  Float32[linkCount * vertexCount * 3]
forces      Float32[linkCount * vertexCount * 3]

topology        Uint32[linkCount * 2]     // START, END
incomingOffsets Uint32[linkCount + 1]     // reverse-incidence CSR
incomingRefs    Uint32[linkCount * 2]     // encoded sourceLink*2 + role

templateWords   Uint32[...]               // rest f32 bits + edge tables
```

The dynamic XYZ fields remain tightly packed at 12 bytes / physical vertex. They MUST NOT be widened to vec4 storage, because that would add 33% memory overhead at million-Link scale.

For the minimum template and 1,000,000 Links each XYZ state buffer is exactly 132,000,000 bytes, so positions/velocities/forces together remain the same 396,000,000-byte numeric payload measured by P4a.

## 4. No per-frame dynamic upload

Initial positions are generated by GPU compute from:
- cached normalized rest positions;
- Link index and topology;
- Link count;
- the exact P2 volumetric seed grid `side/depth/spacing`.

The GPU initializer MUST reproduce the CPU P2 rule:
- center Links on the same O(cuberoot(N)) cubic lattice;
- rotate each mast local +Z toward `seedCenter(end[i]) - seedCenter(start[i])`;
- use the same six-direction Link-index fallback for coincident target centers.

The former one-dimensional `center_x` initialization is forbidden because it recreates the large-network string symmetry defect fixed by #23.

Velocities and forces initialize to zero on GPU.

Ordinary `step()` MUST NOT call `queue.writeBuffer()` for:
- positions;
- velocities;
- forces;
- topology;
- reverse incidence;
- template geometry.

Small control-buffer writes are allowed only when a user actually changes `stiffness` or `simulationSpeed`.

## 5. Reverse-incidence CSR

CPU scatter from apex force to a referenced Link center is unsafe on GPU without float atomics because many source Links may target one Link.

P4b therefore changes the implementation shape without changing the physical result.

For every topology change, build exact reverse incidence:

```text
incomingOffsets[target] .. incomingOffsets[target + 1]
    -> incomingRefs[]
```

Each incoming ref encodes:

```text
sourceLink * 2 + role
role 0 = START apex
role 1 = END apex
```

The GPU hinge-transfer pass runs one invocation per **target Link**:

1. gather every incoming apex force;
2. sum them;
3. add one third of the sum to each central-triangle vertex.

A later separate pass zeros all apex forces.

This is O(2N) total incoming references and requires no float atomic operations.

## 6. Conflict-free spring batches

The accepted cached `template.edgeBatches` remain authoritative for race-free spring accumulation.

Within one batch no two edges share a physical vertex.

For every batch:

```text
for all Links in parallel:
    evaluate each edge in this batch
    add equal/opposite force to its two vertices
```

Batches execute sequentially on the GPU. Links inside a batch are independent.

No atomic force accumulation is required.

## 7. Compute pass order

One GPU physics tick is:

```text
CLEAR_FORCES
for each cached edge batch:
    SPRING_BATCH
HINGE_GATHER
HINGE_ZERO_APEX
INTEGRATE_INTERIOR
PROJECT_HINGES
```

### CLEAR_FORCES

One invocation per physical vertex clears XYZ force.

### SPRING_BATCH

Two-point Hooke law only:

```text
d = Pb - Pa
L = |d|
extension = L - 1
F = stiffness * extension * normalize(d)
```

Coincident edge fallback uses the cached normalized rest direction exactly as the CPU kernel does.

### HINGE_GATHER

One invocation per target Link gathers all incoming apex reactions from reverse CSR and distributes total force 1/3 to the three center vertices.

### HINGE_ZERO_APEX

One invocation per Link clears START/END apex forces after gather has completed.

### INTEGRATE_INTERIOR

START/END apexes are kinematic and skipped.

For every other physical vertex:

```text
v = (v + F * dt) * damping
p = p + v * dt
```

with the same accepted integrator constants as CPU P2:

```text
baseTimeStep        = 1/120
internalDampingRate = 0.8
dt                  = baseTimeStep * simulationSpeed
damping             = exp(-internalDampingRate * dt)
```

### PROJECT_HINGES

One invocation per Link:
- START apex position/velocity <- geometric center of START target;
- END apex position/velocity <- geometric center of END target.

No orientation is transferred.

## 8. Dispatch scaling

A one-dimensional WebGPU dispatch is limited by `maxComputeWorkgroupsPerDimension`.

P4b therefore uses a deterministic 2D dispatch mapper:

```text
linearInvocation =
    global_id.x
    + global_id.y * num_workgroups.x * WORKGROUP_SIZE
```

This allows million-Link workloads without assuming more than the WebGPU minimum 65,535 workgroups per dimension.

## 9. Binding budget

The compute pipeline uses at most seven storage-buffer bindings:

1. positions
2. velocities
3. forces
4. topology
5. incomingOffsets
6. incomingRefs
7. templateWords

plus uniform buffers.

This stays within the WebGPU baseline minimum of eight storage buffers per shader stage.

## 10. Template word layout

To avoid additional storage-buffer bindings, immutable template data is packed into one Uint32 buffer:

```text
restPositions bits  // Float32 bit pattern
edgeA
edgeB
batchEdges
```

Offsets are supplied through a fixed control uniform.

`batchEdges` contains every spring edge exactly once in cached conflict-free batch order.

Each batch owns a tiny immutable uniform containing its offset/count.

## 11. Browser boundary

WebGPU support is optional.

The companion API must distinguish:

```text
UNAVAILABLE      navigator.gpu absent / no adapter
AVAILABLE        adapter + device acquired
DEVICE_LOST      device becomes unusable
```

P4b must not make WebGPU a dependency of the browser-neutral package root.

The eventual package export is a separate companion boundary:

```text
@mts/visual/webgpu
```

Package export/version acceptance is outside this implementation slice.

## 12. Differential witness

P4b provides an explicit diagnostic API that:

1. creates accepted CPU P2 and WebGPU controllers from the same small VisualLinkNetwork;
2. verifies the same initial topology/template;
3. executes the same number of steps;
4. reads GPU positions/velocities back only for the witness;
5. reports maximum absolute position/velocity deltas and pass/fail under a stated tolerance.

Readback is diagnostic only. Ordinary WebGPU `step()` must never read state back to CPU.

The witness must include:
- ordinary Link incidence;
- START self-incidence;
- END self-incidence;
- double self-incidence.

## 13. Resource lifecycle

The controller owns and destroys:
- every storage/uniform buffer it creates;
- temporary readback buffers;
- compute pipelines/bind groups by ordinary GC where the WebGPU API has no explicit destroy.

`destroy()` is idempotent.

After destroy, step/readback operations fail closed.

## 14. P4b acceptance

CI must prove without requiring a physical GPU:

1. reverse-incidence CSR contains exactly 2N refs;
1a. generated WGSL contains the same volumetric seed-center and topology-directed seed-axis contract as CPU P2, with no one-dimensional `center_x` path;
2. self-incidence and high fan-in reverse CSR are correct;
3. template packing preserves exact rest Float32 bit patterns and edge/batch coverage;
4. 2D dispatch covers requested invocation counts including the million-Link minimum workload;
5. generated WGSL exposes the exact six-pass compute sequence entry points;
6. fake-device command witness proves ordinary `step()` performs zero `queue.writeBuffer` dynamic-state uploads;
7. fake-device command witness proves one spring dispatch per cached edge batch;
8. GPU controller exposes the same two Link controls plus global simulationSpeed;
9. diagnostic readback is isolated from ordinary step;
10. real-browser differential API is implemented and fail-closed when WebGPU is unavailable.

A real WebGPU browser run remains required before final P4 acceptance/version publication, because Node CI cannot prove GPU numerical execution.
